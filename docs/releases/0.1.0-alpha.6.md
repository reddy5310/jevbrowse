## What changed since alpha.5 (two review findings, nothing else)

1. **A saved Back/Forward history is judged entry by entry.** Previously it was saved whenever the page the tab ended on was ordinary, so a Sensitive page visited earlier could
   leave its address in the database. Now the whole history stays in memory if ANY entry is Sensitive or Secret (as classified now, so a site you mark Sensitive later removes
   the saved history that mentions it), or an entry cannot be read.
2. **Deleting a workspace is terminal.** Its Time Travel records are deleted with it, and a stale record can no longer recreate it (it used to come back as Personal, with
   different cookies). Time Travel lists only workspaces that exist.
3. **Wording:** this is **address-based Back/Forward**: pages are re-fetched; POST results, form state and per-entry scroll are not restored.

Data note: alpha.5 and alpha.6 share database version 11. Do not open data migrated by alpha.5/alpha.6 with alpha.4 (it refuses newer data and leaves it untouched); use separate
data or a pre-upgrade backup.

## What changed in alpha.5 (unchanged here)

1. **Back and Forward survive a tab sleeping and waking.** The tab's history is saved with it (on disk for ordinary pages, in memory only for Sensitive pages and Private sessions);
   after waking, Back and Forward walk the whole history in order, a new navigation ends Forward as usual, and a second sleep keeps it. Pages are re-fetched from the network when
   walked; per-page scroll position and form contents are not kept. (Removes the alpha.4 limitation.)
2. **Ordinary workspaces can be renamed and deleted** (Workspaces panel: *Rename…*, *Delete…*). Delete closes the workspace's tabs after a confirmation that says what is and is not
   deleted; the Default workspace and temporary sessions are excluded.
3. Database migration 11 (adds saved history to checkpoints); databases from every earlier version still upgrade.

## What changed in alpha.4 (unchanged here)

1. **Typing while a page is still loading** stays protected after the load finishes (protection now ends when the page's document is replaced, not when loading completes).
2. **A playing video that is buffering** stays protected until it is paused or ends; and **pages without video run no polling timer** (it starts when a video first plays).
3. **A stopped agent's pages and workspace are retired** (not selectable, for both Disposable and Private agents); selecting a stale page or pressing "Show its page" after Stop now
   says the session ended instead of failing.
4. **Agent-profile cleanup uses the workspace's real container** (a Private agent's profile was previously targeted as Disposable and left behind) and is **retried** until the
   profile is really deleted.
The clean-Windows checklist's permission step now says "For 1 hour" (what the prompt actually offers).

## What changed since alpha.2 (in alpha.3)

**Unfinished work keeps a tab awake.** A review of what automatic sleep protects found four gaps, now fixed: a page holding only a half-typed **password** (that field was
excluded, so the tab was put to sleep and the text lost), typing inside an **iframe**, a file **upload in flight** (fetch/XHR with a file, blob or form body), and a long or
live **video playing without sound**. Short muted loops (hero clips, ads) are deliberately ignored. The tab menu and Explain say why a tab is being kept awake. The person can still
put it to sleep on purpose, after a warning. **Back/Forward history is NOT kept when a tab sleeps** (only address and scroll position): disclosed below.

## What changed in alpha.2 (unchanged here)

Site permissions: **This tab ▾ ▸ Site permissions…** lists remembered decisions for the current origin and profile and resets them (the next request is asked again; a camera or
microphone stream already running is not stopped). **Clear website data…**: cookies and website storage for the current identity profile only (per-site deletion is not
available); signs you out; does not delete downloads, other profiles or Browser Memory. **Resume**: the last ordinary workspace and active tab return after a restart, only
that tab awake; Private, Disposable and agent sessions are never remembered. **Private downloads** ask first and say the file stays after the session ends; agent pages cannot
download. **Popup sign-in is unsupported** (recorded by a check; the status line says so). A missing WebView2 runtime shows a message with a link and a Quit button.
All ten review fixes from alpha.1 are unchanged.

## Prerequisites, data and backup

Windows 10 (19041+) or 11, x64; Microsoft Edge WebView2 Runtime (a message explains what to do if it is missing). No installer: extract and run `JevBrowse.App.exe`;
Windows shows a SmartScreen warning because the build is unsigned. Data: `%LOCALAPPDATA%\JevBrowse`. Backup: close the app, copy that folder; restore by copying it back. A
build that finds data from a NEWER version refuses to open it and leaves it untouched.

  resume, the simulated missing runtime and the clear-data dialog; **16 engine steps** (permission reset, per-profile clearing, Private-download prompt, recorded
  popup-login behaviour).
- Mutation checks: making the Private-download prompt always allow fails "Cancel saves nothing"; restoring the old password rule fails 3 of the 10 protection steps (the tab is put to sleep).
- Review findings: 6 regressions (`ReleaseBlockerRegressionTests`); with the old behaviour restored 4 of them fail.
- Back/Forward across sleep on the packaged build: `--history-check`, 13 steps; mutation check: with the history not restored, 8 of 13 steps fail (the old behaviour).
- Unfinished-work protection on the packaged build: `--protection-check`, 19 steps (idle page left alone; password-only, iframe, during-load typing, upload, silent and buffering video; and Disposable and Private agents retired). Mutation check: restoring the three audited behaviours fails 3 steps (typing lost after load, buffering video unprotected, a Private agent's profile left behind).
- Process-cleanup scripts: every script that stops processes uses `scripts/ProcessScope.ps1` (id AND start time; a real-process self-test proves a reused id is not stopped).
- Timeouts: every automated wait is bounded; a timeout is a failure (or inconclusive), never a pass.
Development-only setting in these runs: `JEVBROWSE_DATA_DIR` (data kept off C:).

## Known limitations

Unsigned, portable, no updater. **Popup-based sign-in does not work.** Clearing website data is per profile, not per site. A file saved from a Private session stays after the session
ends (you are told). Screenshot (agent) is experimental, off by default; its "never visible even briefly" claim is unproven. The agent endpoint is off unless turned on. A power cut
can lose the last few saved changes. First launch with no network starts without Shield's filter lists until they download.

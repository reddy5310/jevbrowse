# JevBrowse 0.1.0-alpha.7 — tester handoff

**This is a request for acceptance testing, not a release.** JevBrowse is not public yet. You are being asked to run one checklist on your own machine and
report back PASS/FAIL/what-you-saw per row — that is the whole task, about 20–30 minutes. Please do not share this file, the ZIP, or the results outside
whoever asked you to test.

## What to do

1. **Get the file.** Whoever sent you this handoff should also send you `JevBrowse-0.1.0-alpha.7-win-x64.zip` (about 90 MB) and `SHA256SUMS.txt`, as
   separate attachments/links. This document does not itself carry the file.

2. **Check the checksum before running anything**, in PowerShell, in the folder where you saved the zip:
   ```powershell
   Get-FileHash .\JevBrowse-0.1.0-alpha.7-win-x64.zip
   ```
   The `Hash` it prints must equal:
   ```
   d6a791fe7a898f1afe91b3cb175693a47986296bc235796548f930031989e65f
   ```
   If it does not match, **stop and say so** — do not run the file. (It should also match the line for that filename in `SHA256SUMS.txt`, if you have
   that file too.)

3. **Use a machine with no development tools installed** and no `JEVBROWSE_*` or `WEBVIEW2_*` environment variables set — a normal Windows account, or a
   VM, is the point of this test. Extract the zip to a normal folder (e.g. `Downloads\JevBrowse`).

4. **Run the checklist:** [CLEAN_WINDOWS_CHECKLIST.md](../CLEAN_WINDOWS_CHECKLIST.md) — 21 rows, about 20–30 minutes. It is self-contained; you do not
   need the source code or any of JevBrowse's other documentation to follow it. For each row, write down **PASS**, **FAIL**, or what you actually saw if
   it differs from what the row expects.

5. **Report back**, in whatever form is easiest: the checklist with your notes, or a short PASS/FAIL list against the row numbers plus any FAILs
   described in your own words. Include the hash from step 2 in your report, so whoever reads it knows exactly which build you tested.

## Quick facts, in case they come up

- **What it needs:** Windows 11 (or 10) x64, and the Microsoft Edge WebView2 Runtime — already present on most Windows 11 machines with Edge installed;
  if it's missing, JevBrowse itself will tell you and offer the download (that message is one of the checklist rows).
- **It is unsigned.** Windows SmartScreen will warn on first run ("Windows protected your PC"). That is expected for this stage; click "More info" then
  "Run anyway." A real release will need a code-signing certificate before this goes away — not yet purchased.
- **Where your data goes:** `%LOCALAPPDATA%\JevBrowse` (a normal Windows Explorer path — paste it into the address bar). Deleting that folder removes
  everything JevBrowse has stored for you, including a Downloads test file the checklist creates.
- **Nothing about this test is expected to touch anything outside that folder and, for one specific row, the "default browser" registry entry the
  checklist itself tells you how to check and undo.** No other Windows setting should be changed by anything in the checklist.
- **What this build is NOT yet:** independently security-reviewed (a specific mechanism — how a web page is stopped from triggering a browser shortcut
  itself — is still open; see `docs/security/CHORD_TOKEN_REVIEW.md` if you're the one doing that review, not this checklist) or run on a clean machine
  before now, which is exactly why this handoff exists.
- **An automated bench check (not part of this checklist) is reproducibly failing before it reaches the Private-download checks, root cause not yet
  found** — confirmed unrelated to the security fix above by direct testing, but that is the only thing ruled out; see `docs/releases/0.1.0-alpha.7.md`
  for exactly what did and didn't run. Because of this, **row 9 is the only confirmation this alpha has that Private-session downloads behave correctly**
  — please follow it exactly, exercising Cancel and Continue as two separate downloads and checking the file outcome after each, and confirm in row 16
  that ending the Private session removes the download from the list while leaving the file itself in place.

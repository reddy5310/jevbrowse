## New for people
- **Bookmarks**: Ctrl+D adds or removes; Ctrl+Shift+O opens a searchable list; **import** the HTML file exported by Chrome, Edge, Firefox or Brave (web addresses only). Private sessions cannot add bookmarks.
- **Search engine choice**: DuckDuckGo (default), Google, Bing, Brave Search, Startpage, Ecosia (More menu, Bookmarks and search engine).
- **History** (Ctrl+H): search, Forget one entry, Clear all. Never records Private or agent sessions or pages classed Sensitive/Secret (banking, health).
- **Downloads list** (Ctrl+J): newest first, finished or not, **Show in folder**. Files are never opened from the list. A Private-session download is listed in memory only.
- **Per-site zoom** (Ctrl+ / Ctrl- / Ctrl+0): the familiar 25%..500% ladder, remembered by site, not remembered in Private/agent sessions or on Sensitive pages.
- **Links from other apps**: a link clicked elsewhere opens in the running JevBrowse (a new tab in the default workspace, never in a Private session); only http/https. **Make JevBrowse your default browser** registers it for the current user and opens Windows Settings; Windows requires you to choose it there. *Remove JevBrowse from the browser list* undoes the registration.

## Local interaction pass (this machine, NOT clean-Windows evidence)
`scripts\interaction-pass.ps1` drives the extracted candidate ZIP with real key presses and UI Automation, a fresh data folder and a local web server ([results](0.1.0-alpha.7-interaction-pass.json)). 15 rows PASS, 0 FAIL on the final ZIP: Ctrl+D add/remove/add; the bookmarks panel; the **real file picker** importing an export (a `javascript:` entry not imported); clicking an imported bookmark; choosing Google and searching (and the choice surviving a restart); History with Forget and Clear (Cancel keeps, Clear removes, the dialog says what is not deleted); a real download listed with **Show in folder** opening Explorer on it; marking a site Sensitive removing its earlier history and stopping new records; zoom by keyboard, reload and reset; bookmarks after a restart; a second copy extracted to another folder is refused with a message.
**It found a real defect, fixed in this build:** with the page focused, Ctrl+plus zoomed the page once through JevBrowse and then the engine's own zoom stacked on top (two zoom systems; per-site zoom wrong). The engine's zoom is now off and Ctrl+plus/minus/0 and Ctrl+wheel (a touchpad pinch) are taken from the page and handed to the app. The pass failed on the previous build and passes on this one.
The same pass also showed that **a second copy extracted to a different folder does not see the first through the app-instance service** (it is scoped to the program's identity), so it is the data-folder lock that refuses it; the lock is what protects the data.
NOT TESTED here: 14d (the "already saved" line is shown only in the status line, which UI Automation did not expose: an accessibility note for later), row 19 (default browser: opening that dialog writes to the current user's registry and Windows Settings, which this machine's owner asked to leave alone), the Private-session rows through the UI (covered by the automated engine check), and rows 3, 5, 7-10, 12, 13 (real account, upload, permission prompt, clear data, Private restart, offline, missing runtime).
Observation, not fixed: after typing a search in the address bar, the box keeps showing the typed words rather than the results page address (the tab title and host are correct).

## Corrective pass (after an independent static review; four findings confirmed and fixed, one mismatch removed)
1. **One copy per data folder.** The single-instance guard used the program's folder while storage used `%LOCALAPPDATA%\JevBrowse`, so copies extracted to different folders could open the same database. Startup, storage and the crash log now share one resolver (`DataLocation`), the guard is keyed by it, and an exclusive lock file in the data folder is held for the life of the process. If a hand-over fails or the lock is taken, the copy stops with a message instead of carrying on. Verified with real processes (a copy started while another process held the folder shows the message and exits with code 1). The default-path equality is unit-tested only: no real run touched `%LOCALAPPDATA%`; the clean-Windows run uses it.
2. **History and zoom follow class changes.** Marking a site Sensitive (and a page turning Sensitive later, for example when a card field appears) now removes that site's saved history and zoom. A Private tab on the same site cannot erase an ordinary tab's history. Mutation-checked (removing the late purge, or the sweep, fails a test each).
3. **Download ownership.** A download's owner (container and workspace) is fixed when the page is created, not looked up when the download ends; an unknown owner is treated as Private (memory only); ending a Private session removes its download names from the list (the files stay). Verified in the engine check (31 steps).
4. **Release publishing.** A package built by one run is no longer what a second run publishes: publishing (`scripts\publish-release.ps1`, or the two-step workflow) refuses unless the zip's SHA-256 equals the hash you tested and matches `SHA256SUMS.txt`, and never attaches symbols. A tag push does nothing. **GitHub Actions is currently blocked by a billing/spending-limit notice on the account, so the workflow's package step could not be re-run and the corrected workflow is untested; the local script was exercised (matching hash passes, another hash is refused).**
5. Registration no longer claims `.htm`/`.html` file associations (the launch path only opens web addresses).

## Verification (what was actually checked)
- Unit tests for each feature, including regressions that fail without the rule they protect. Mutation-checked: removing the scheme filter from bookmark import fails 2 tests (the first version of that test could not fail: it passed with the filter removed, and was strengthened); removing the class gate from the history recorder fails 2 tests.
- Real engine (`--additions-check`, 30 steps): a Private tab cannot bookmark; an ordinary page is in history and a Private page is not; an ordinary download is listed with its file present and a Private one is in memory only; zoom applies, is remembered per site, survives a reload and reset forgets it; Private zoom writes nothing.
- Two real processes (`external-link-check.ps1`, 6 checks): second start hands the link over and exits; a `javascript:` argument is ignored; a cold start with a link opens it.
- Default-browser registration: entries are current-user only; a real write/remove round-trip was run against a scratch registry key. **The real Windows default was not changed and the Settings hand-off was not clicked through.**

## Not verified / limits
- The new panels, the import file picker and the shortcuts were exercised through the same code paths, not by clicking each control; a clean-machine pass should click them.
- Zoom is page zoom applied by script (the WinUI web view does not expose the engine zoom): pages that size things in viewport units can differ.
- Not built: bookmark export, a bookmarks bar, download progress/cancel/retry, full-screen video (untested with the engine defaults), managed sign-in pop-ups (still unsupported).
- Still open and not code: signing certificate, update path, clean-Windows run, display scaling, high contrast, screen reader, the pixel-level no-flash screenshot observer.
